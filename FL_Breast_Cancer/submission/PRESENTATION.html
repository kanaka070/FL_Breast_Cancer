Research prototype · Comparative study

Privacy-Preserving Federated Learning for Collaborative Breast Cancer Diagnosis

Centralized Logistic Regression · Federated Averaging · Experimental DP-FedAvg

Wisconsin Diagnostic Breast Cancer benchmark · Three simulated hospitals

Academic demonstration only. Not for clinical diagnosis.

01 · Question

Can model training be distributed without pooling records?

Centralized

One Logistic Regression model fit on pooled training data.

FedAvg

Three simulated clients fit locally; coefficients/intercepts aggregated.

DP-FedAvg

Experimental clipping plus Gaussian perturbation; end-to-end privacy is unproven.

The client partitions run in one process; these are not independent hospitals or secure services.

02 · Data and method

Reproducible benchmark evaluation

  • UCI WDBC: 569 observations, 30 numeric features; ID excluded.
  • Seeded, stratified 80/20 split: 455 training records and 114 held-out test records.
  • Additional CV uses training records only; scaling is fit inside each fold.
  • All three primary approaches use Logistic Regression.
  • Hospital partitions are labelled simulated throughout.

Dataset: UCI Machine Learning Repository, Breast Cancer Wisconsin (Diagnostic), dataset 17.

06 · Application workflow

Approval and inference are explicit

  1. Inspect actual saved comparison rows and select a candidate.
  2. Explicitly approve; active-model pointer persists.
  3. Prediction loads only the approved model and its matching scaler.
  4. Validate all 30 canonical WDBC features and display class probabilities.
  5. Retraining requires explicitly confirmed labels; predictions cannot be labels.
  6. Evaluate a separate candidate, then explicitly approve; stale candidates are rejected.
07 · Privacy, honestly stated

Noise addition is not an end-to-end proof

Implemented

Patient-gradient clipping, Gaussian noise, and an RDP-style composition estimate.

Historical accountant row

ε ≈ 17.0065 at δ = 10⁻⁵, noise multiplier 2, 30 rounds.

Unresolved

Coordinator sees pre-noise clipped client contributions; pooled data-dependent scaler is not accounted.

That epsilon is conditional on mechanism assumptions, not a verified deployment-wide guarantee. A complete threat model, sensitivity/adjacency justification, preprocessing accounting, release composition, and independent accountant review are required.

08 · Limitations and next steps

Evidence supports a prototype, not clinical deployment

  • Small public benchmark; one historical held-out split for the primary results.
  • Simulated clients, no authentication or secure aggregation boundary.
  • Historical baseline training-time comparability unavailable.
  • SHAP not run: dependency absent; no explanation values fabricated.
  • Future: independently verify DP design/accounting, repeat federated runs, and evaluate governed external cohorts.

Conclusion: the workflow is demonstrable and model approval is explicit; generalization and formal privacy remain open research issues.
